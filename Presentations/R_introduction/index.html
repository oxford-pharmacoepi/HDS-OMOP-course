Introduction to R

R programming language

R first appeared in 1993. It is a programming language designed for working with data and statistics.

R is usually interpreted: we write commands and R runs them without a separate compile step.

2 + 2
[1] 4

Find your way around RStudio

R does the calculations. RStudio gives us places to write code and see what happened.

  • Source: write and save a script. This pane appears when you open a file.
  • Console: run commands and read their output or errors.
  • Environment: see objects created in the current R session.
  • Files, Plots, and Help: find files, see figures, and read documentation.

The panels can be arranged differently on your computer. Look for their names rather than their position.

What is an R Project?

An R Project is a folder for one piece of work, with a small .Rproj file that RStudio uses to reopen it.

  • Keep scripts, data, and results together.
  • Open the .Rproj file to return to the project.
  • Use paths relative to that folder so your code is easier to share.

Think of it as a home for the exercise.

YOUR TURN Create your first project

In RStudio:

  1. Choose File → New Project… → New Directory → New Project.
  2. Name it practical and choose a folder you can find again.
  3. Click Create Project. Check the project name at the top-right of RStudio.
  4. Choose File → New File → R Script and save it as practice.R inside the project.

Use the Files panel to create folders called data and Results. The names and capital letters should match the examples.

A simple project layout

practical/
├── practical.Rproj
├── practice.R
├── data/
└── Results/

Save input files in data and things you create in Results. Bigger projects often have an R folder for scripts too.

The .Rproj file helps RStudio open the project. Your .R script contains the code you want to keep.

Write, run, save

Type 2 + 2 into practice.R, place the cursor on that line, and click Run. You can also use Ctrl+Enter on Windows/Linux or Cmd+Enter on Mac.

The command is sent to the Console and the answer appears there. Select several lines to run them together.

Saving stores your code in a file. Running asks R to execute it. Save and run after changing an example so the file and the result agree.

A Console > means R is ready. If you see +, it is usually waiting for something such as a closing bracket or quote; press Esc and check the command.

Use a function

A function does a job. Put the inputs, called arguments, inside its brackets:

ages <- c(23, 35, 41, 52)
mean(ages)
[1] 37.75
length(ages)
[1] 4

Missing values are written as NA. Some functions need us to decide how to handle them:

scores <- c(7, 8, NA)
mean(scores, na.rm = TRUE)
[1] 7.5

Here, na.rm = TRUE asks mean() to leave missing values out of the calculation. Use ?mean in the Console to read its help page.

You can write a function too

sumFun <- function(a, b) {
  a + b
}

sumFun(5, 6)
[1] 11

a and b are the inputs. The code between { and } says what to do with them.

For now, most of our work will use functions that other people have already written. You do not need to memorise how to write your own before continuing.

Packages in R

A package is a collection of functions, documentation, and sometimes data that people develop and share.

Many packages are distributed through CRAN, the Comprehensive R Archive Network. CRAN hosts packages and checks submitted updates; package authors maintain the packages themselves.

Install a package into your R library when you first need it:

install.packages("tibble")
# Or, if pak is installed:
pak::pkg_install("tibble")

You normally do not need to reinstall it each time you open RStudio.

Load a package when you use it

library() makes a package’s functions available in the current session:

library(tibble)
tibble(a = 1)
# A tibble: 1 × 1
      a
  <dbl>
1     1

You can also call a function with its package name:

tibble::tibble(a = 1)
# A tibble: 1 × 1
      a
  <dbl>
1     1

In this training, we will usually use library() at the start of a script. Short, one-off calls may use ::.

Put the library() calls in your saved code too. A new R session needs to load the packages again.

Meet the tidyverse

The tidyverse is a collection of packages that work well together for common data tasks:

  • tibble: create and display tables.
  • dplyr: filter rows, change columns, and summarise data.
  • readr: read files such as CSVs.
  • tidyr: reshape tables.
  • ggplot2: make plots.

We will load the packages we need for each example. The functions often take a table as their first input.

Our first table

library(tibble)

people <- tibble(
  name = c("Alex", "Sam", "Jo"),
  age = c(24, 31, 17),
  group = c("A", "B", "A")
)
people
# A tibble: 3 × 3
  name    age group
  <chr> <dbl> <chr>
1 Alex     24 A    
2 Sam      31 B    
3 Jo       17 A

Each row describes one person. Each column holds one type of information.

A tibble is a type of data frame. Think of both as tables with named columns.

Pick a column or inspect the table

people$age
[1] 24 31 17
mean(people$age)
[1] 24
nrow(people)
[1] 3

$ selects a named column. nrow() counts rows.

names(people)
[1] "name"  "age"   "group"

names() shows column names. This is useful if a later example says that a column cannot be found.

Filter and change a table

library(dplyr)

adults <- filter(people, age >= 18)
adults <- mutate(adults, age_next_year = age + 1)
adults
# A tibble: 2 × 4
  name    age group age_next_year
  <chr> <dbl> <chr>         <dbl>
1 Alex     24 A                25
2 Sam      31 B                32

filter() keeps the rows that match a condition. mutate() creates or changes columns.

Inside these functions, we can write age directly because they look for columns in the supplied table.

The pipe operator |>

The pipe passes the result on its left into the function on its right, usually as the first argument.

We can write the previous example as a sequence of steps:

adults <- people |>
  filter(age >= 18) |>
  mutate(age_next_year = age + 1)
adults
# A tibble: 2 × 4
  name    age group age_next_year
  <chr> <dbl> <chr>         <dbl>
1 Alex     24 A                25
2 Sam      31 B                32

Read it as “take people, keep adults, then add their age next year”. The pipe is built into R from version 4.1 onwards.

Summarise a table

people |>
  filter(age >= 18) |>
  count(group)
# A tibble: 2 × 2
  group     n
  <chr> <int>
1 A         1
2 B         1

Some verbs you will see again:

  • filter(): keep rows.
  • select(): keep columns.
  • mutate(): create or change columns.
  • summarise(): calculate summaries, such as a mean.
  • arrange(): sort rows.

Find files with here

library(here)
here()
[1] "/home/runner/work/HDS-OMOP-course/HDS-OMOP-course"

here() finds the project root. We can build paths from it without typing a computer-specific address:

here("data", "data1.csv")

This points to data/data1.csv inside your project. It does not create the file: we will download it in the Quarto session.

Reading a CSV: a preview

A CSV stores a table as plain text. The first line usually contains column names.

After downloading data1.csv in the Quarto session, we can read it with:

library(readr)
library(here)

data <- read_csv(here("data", "data1.csv"))
head(data)

Keep this example for later. read_csv() brings the file into R; head() displays the first few rows.

If something goes wrong

  • Object not found: check the spelling and run the line that creates the object first.
  • Could not find function: load its package with library().
  • No such file: check the active project, folder, filename, and capital letters.
  • Unexpected symbol: check quotes, commas, and brackets near the reported line.

Start at the first error, fix it, and rerun that part. A message or warning is not always an error; read what it says before moving on.
